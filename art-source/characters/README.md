# Imperium character handoff

These three self-contained glTF 2.0 files export three Chapter V figures as the game's own character code builds them: Marcellus, Lucan and a Persian guard. They contain the near-detail full body, connected clothing, equipment, face morphs, skin joints, embedded PNG material maps and sampled idle, walk, attack and block clips. Units are metres; +Y is up and +Z is forward.

Since 0.37 the battle figures wear generated character bodies ([the asset pipeline](../../docs/asset-pipeline.md)) over this rig, kit and animation. These files show the code-built figure without one: what the game draws until a figure's body arrives, or if it fails to load. The generated bodies themselves are the GLBs in `assets/models/characters/`.

The game continues to build the shared rig from its editable JavaScript geometry and JSON performance sources. These exports are an interchange and art-review handoff, not a second set downloaded by the player. Overview meshes remain generated by the runtime's tested simplification and batching path. The files are excluded from the website build and offline download.

Sources:

- `src/showcase/actors.js`, `actor-costume.js`, `actor-helmet.js`, `character-detail.js`: original geometry, tailoring and fittings.
- `src/showcase/actor-identity.js` and `actor-wardrobe.js`: faces, ages, clothing colours and cast identity across all twelve chapters.
- `scripts/character-sources/performance-v034.json`: editable joint performances; export with `node scripts/build-character-performance.mjs`.
- `src/showcase/actor-pose.js` and `paired-contact.js`: contact timing, foot planting and coordinated weapon/shield contact.
- `scripts/character-glb.mjs`: deterministic glTF writer with embedded PNGs, explicit units, skin weights and clips.

Run `npm run art:handoff` with Sharp available; it writes here from any working directory. Alternatively set `ART_SHARP_MODULE` to an installed Sharp entry point. Sharp is used only to decode the existing WebP complexion images and is not a project dependency. `manifest.json` records each export's hash, topology inventory, exact subject configuration and a digest of the character source it came from.

`npm test` checks the committed files (hashes, glTF structure, skins, maps and clips) but not whether they match the current character code, so a character change does not fail the tests. `npm run audit:handoff` reports a stale export, and `npm run verify` prints the same notice without failing. Re-export only when the characters actually change: an export is repeatable on one machine, but a different Node.js or Sharp version can produce different bytes.

Import a GLB into a glTF-capable DCC, preserve the named skeleton, UVs and metre scale, and inspect all four clips before proposing a replacement. The exported standard PBR materials do not reproduce the runtime's cloud shadow or warm skin-fill shader; judge those in the running game. Exporting this rig does not turn the existing MakeHuman anatomy into a new specialist sculpt or the authored performances into motion capture.

Original costume geometry, texture fields and authored clips are project work. The retained MakeHuman body/head source and its adaptations use the existing CC0 provenance recorded in `docs/asset-manifest.json` and `vendor/makehuman/`. No private planning documents are included.
